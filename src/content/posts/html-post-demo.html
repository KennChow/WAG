什么时候该用 HTML 写

Markdown 覆盖了绝大多数写作场景。选择直接写 HTML，通常是因为下面这些原因：

  • 内容本身就是从别处导出的 HTML 片段，不想再转一道 Markdown；
  • 需要精确控制结构，比如复杂表格、带 colspan 的表头、自定义的语义标签；
  • 要嵌入一段只属于这篇文章的交互式内容。

frontmatter 写在注释里

HTML 没有 Markdown 那样的 frontmatter 约定，所以这里约定：文件开头的 <!--astro ... --> 注释块就是 frontmatter，里面按 YAML 写。 字段和 Markdown 文章完全一致：title、description、 pubDate、updatedDate、tags、draft、cover。

其中 title 和 pubDate 是必填的，缺了会在构建期直接报错，而不是悄悄生成一篇无标题文章。

目录锚点是自动补的

你会注意到这篇文章右侧同样有目录。上面这些 <h2> 我并没有手写 id， 是构建时用 github-slugger 自动补上的——和 Markdown 文章用的是同一套算法，所以两类文章的锚点风格完全一致。 如果你自己写了 id，那就以你写的为准。
