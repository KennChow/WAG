01这个网络

三条分支各查一次表再过两层全连接，汇聚后接一层输出。

这是推荐模型里最常见的形状。三条分支互不依赖，理论上可以同时算； 汇聚之后的 concat、fc、out 必须串行。 下面看 MiniDAG 怎么把这个直觉变成具体的流号。

02第一步：分层

拓扑排序之后，按最长前驱路径给每个节点定层。

三条分支形状相同，所以同名位置的节点落在同一层：三个 emb 都在层 0， 三个 mm?1 都在层 1，三个 mm?2 都在层 2。 concat 的前驱是三个层 2 的节点，所以它在层 3。

分层的结果给出每层的节点数，也就是 global_level_loads：

层012345
节点数333111

前三层各有 3 个节点，可以并行；后三层各只有 1 个节点，只能串行。 这个数组后面还要用到：MainStream 判断该不该强制回主流，看的就是它。

03第二步：路径覆盖成单元

用最少的链覆盖整张图，每条链成为一个单元。

算法不给单个节点挑流，而是先把节点串成链。这里用的是 HopcroftKarp 二分匹配求最小路径覆盖， 12 个节点被三条链盖住，于是得到 3 个单元。同一个单元里的节点必定分到同一条流。

04第三步：给每个单元挑流

三个单元，三步决策，每步比较几个候选流。

打分公式如下，四项加权求和，取最小的那个候选。

步 1　单元 0（6 个节点）

此时一条流都还没有，唯一的候选就是新开流 0。 新流上只有这个单元，window_loads 是 [6]， 只有一个元素，方差为零。

候选eventwindow_balanceload新流total
新开流 00[6] → 6 + 0 = 6.00610 + 24 + 6 + 2 = 32

步 2　单元 1（3 个节点）

候选有两个：单元 1 的后继单元 0 已经在流 0 上，所以流 0 进入候选； 再加上新开一条流。

候选eventwindow_balanceload新流total
留在流 00[9] → 9 + 0 = 9.00900 + 36 + 9 + 0 = 45
新开流 11[6,3] → 6 + 2.25 = 8.25313 + 33 + 3 + 2 = 41

留在流 0 的话两个单元同在一条流上，负载 9，方差为零但峰值高。 新开一条流让负载变成 6 和 3，峰值降到 6，方差是 ((6−3)/2)² = 2.25。付出的代价是 1 条跨流边（3 分）加固定罚分（2 分）， 总账 41 比 45 更划算，于是分出第二条流。

步 3　单元 2（3 个节点）

候选有三个：邻居所在的流 0、当前最轻的流 1、以及新开一条流。 上限是 3 条流，所以新流还开得出来。

候选eventwindow_balanceload新流total
留在流 00[9,3] → 9 + 9 = 18.00900 + 72 + 9 + 0 = 81
放到流 11[6,6] → 6 + 0 = 6.00603 + 24 + 6 + 0 = 33
新开流 21[6,3,3] → 6 + 2 = 8.00313 + 32 + 3 + 2 = 40

这一步选中的是中间那个候选。放到流 1 之后两条流各 6 个节点， 方差正好为零，window_balance 降到 6，是三个候选里最低的。 新开第三条流虽然把单元 2 单独放着，但三条流变成 6、3、3，反而不如两条 6、6 均匀。

05结果

两条流，各六个算子。

06换成 MainStream 会怎样

同一个网络，三条流，每条分支各占一条。

MainStream 的打分不含累计负载，改用同层冲突，并给主流一个奖励项。 在这个网络上它的三步是这样走的。

步候选event同层冲突主流奖励total
1流 0（唯一候选）0030 + 0 + 2 − 12 = −10
2留在流 00300 + 12 + 0 = 12
2新开流 11003 + 0 + 2 = 5
3留在流 00300 + 12 + 0 = 12
3放到流 11303 + 12 + 0 = 15
3新开流 21003 + 0 + 2 = 5

步 1 单元 0 是唯一候选：它在层 3 到层 5 上独占，全图那三层各只有一个节点， 触发了强制回主流的规则。主流奖励是 3 个独占节点乘权重 4，总分成了负数。

步 3 是两种策略分道的地方。LoadBalance 把单元 2 放进流 1，因为那样两条流各 6 个节点最均匀； MainStream 看到单元 2 与流 1 上的单元 1 完全同层，冲突是 3， 于是宁可再开一条流。最终结果是 6、3、3，每条分支独占一条流。

同一个网络，两个答案都成立

LoadBalance 追求各流的量接近，得到 6 和 6； MainStream 追求同层不争用，得到 6、3、3。 前者省一条流，后者让三条分支真正同时开跑。 哪个更快取决于分支本身的耗时，以及硬件上多流切换的开销。

07自己跑一遍

不需要 NPU，只要能导入 minidag。

把下面这段存成文件直接执行，就能得到本文所有数字。

# source ~/AscendMsTest/cann-9.2.0/set_env.sh 之后执行
import minidag

NODES = [("emb_a","GatherV2"), ("mm_a1","MatMul"), ("mm_a2","MatMul"),
         ("emb_b","GatherV2"), ("mm_b1","MatMul"), ("mm_b2","MatMul"),
         ("emb_c","GatherV2"), ("mm_c1","MatMul"), ("mm_c2","MatMul"),
         ("concat","ConcatV2D"), ("fc","MatMul"), ("out","NetOutput")]
EDGES = [("emb_a","mm_a1"), ("mm_a1","mm_a2"), ("mm_a2","concat"),
         ("emb_b","mm_b1"), ("mm_b1","mm_b2"), ("mm_b2","concat"),
         ("emb_c","mm_c1"), ("mm_c1","mm_c2"), ("mm_c2","concat"),
         ("concat","fc"), ("fc","out")]

g = minidag.DAGGraph("demo")
node = {n: g.add_node(n, t) for n, t in NODES}
for a, b in EDGES:
    g.add_edge(node[a], 0, node[b], 0)

plan = minidag.allocate(g, max_stream_num=3,
                        merge_strategy=minidag.MergeStrategy.LOAD_BALANCE)
for n, _ in NODES:
    print(n, plan.get_stream_id(node[n]))

把 LOAD_BALANCE 换成 MAIN_STREAM 就能看到第 6 节的结果。 想看每一步的打分，用 benchmarks/minidag_equiv/replay_minidag.py 里的 install_score_probe()，它包住两个打分函数，把每次比较都记下来。

本文所有数字由 minidag 实际执行产生，权重取自 _merger.py:83 的默认值。
窗口宽度 6 层，流数上限 3 条，repair_moves 为 0。
